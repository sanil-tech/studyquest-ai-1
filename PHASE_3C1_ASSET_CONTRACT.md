## 3. ASSET APPROVAL LIFECYCLE & SAFETY RULE

```text
[DRAFT] ──► [UNDER_REVIEW] ──► [APPROVED] ──► [PUBLISHED] ──► [ARCHIVED]
```

### AI Safety Rule (`AI quality score !== human approval`)
- When an asset is generated by AI (`created_source === "ai_generated"`), `sanitizeAiGeneratedAsset` automatically sets its status to `DRAFT` or `UNDER_REVIEW`.
- An AI-generated asset **CANNOT** be set to `APPROVED` or `PUBLISHED` without an explicit `approved_by` admin User ID. `validateAsset()` enforces this invariant and throws a validation error if violated.

## 4. CONTENT COVERAGE STATE CALCULATOR

`getAssetCoverageState(availableAssets)` evaluates the availability of content assets for a given curriculum identity without fabricating placeholder content:

```javascript
export const COVERAGE_STATES = Object.freeze({
  MISSING: "MISSING",
  DRAFT: "DRAFT",
  UNDER_REVIEW: "UNDER_REVIEW",
  APPROVED: "APPROVED",
  PUBLISHED: "PUBLISHED",
});
```

### Hard Safety Rule
If no approved assets exist for a curriculum identity, `getAssetCoverageState` returns `"MISSING"`. Systems MUST NOT render `"Kandungan tidak tersedia..."` or any fabricated placeholder text to students.

## 5. PUBLISHED SNAPSHOT IMMUTABILITY INVARIANT

`verifyPublishedSnapshotInvariant(publishedLessonVersion, compiledBlocks, updatedLibraryAssets)` guarantees that changes to assets in the Content Library do **NOT** alter previously published `LessonVersion` snapshots.
